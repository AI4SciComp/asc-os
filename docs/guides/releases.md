# Releases

Version 0.1.0 is the first alpha distribution, dated 2026-09-15. Its
[GitHub release](https://github.com/AI4SciComp/asc-os/releases/tag/v0.1.0)
provides a wheel and source archive. See the [installation guide](installation.md)
for the commands to install these assets.

Local builds do not publish a GitHub release or upload to a package index.
The repository's `AGENTS.md` prohibits publication unless a maintainer
explicitly authorizes an exception. The v0.1.0 exception authorizes a GitHub
release with the wheel and source archive. PyPI publication is outside its
scope.

## Prepare metadata

Keep the version in `pyproject.toml`, `src/asc_os/version.py`, `CITATION.cff`,
and `uv.lock` aligned. Run `uv lock` after changing the package version.
Documentation and generated manifest ownership records use the runtime
version. Update `CHANGELOG.md` with the user-visible changes; add a release
date only when publication occurs.

Generator version changes alter generated bytes. Review changes to the pilot's
golden digests against a clean temporary copy, preserving the authored inputs
and checking that only the intended version metadata and dependent hashes
change.

## Validate and build

Run from the checkout:

```console
uv sync --frozen --all-groups --all-extras
make format-check lint typecheck test security-test examples docs check
make package-test
```

Tests enforce at least 90% branch coverage separately from total coverage.
`make package-test` builds a source archive and a wheel from that archive,
checks their metadata, and installs each into an isolated temporary uv tool
environment. It exercises the command outside the checkout, verifies bundled
resources, validates a new research project from a subdirectory, and checks
dry-run behavior and repeat-build idempotency. The wheel is tested with base
dependencies and the source archive with the MCP extra.

Artifacts remain under ignored `dist/`:

- `asc_os-0.1.0-py3-none-any.whl`
- `asc_os-0.1.0.tar.gz`

Install the validated wheel using the [installation guide](installation.md).
Do not commit distributions, caches, coverage output, or build logs.

## Publication boundary

CI builds and tests distributions as review artifacts. It has no package
upload or release creation step. A public release needs an explicitly
authorized destination, reviewed source commit, release notes, and passing
validation evidence. Build the assets from the tagged source, attach only the
intended wheel and source archive, and verify the downloaded assets against
the locally validated bytes. Version 0.1.0 is distributed through GitHub;
there is no PyPI publishing step.
